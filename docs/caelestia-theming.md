# Caelestia theming: real Catppuccin, and a theme picker

How to get Catppuccin colours out of caelestia-shell, and how to switch themes
without editing anything.

## Why the bundled `catppuccin` scheme doesn't look like Catppuccin

caelestia-cli ships a scheme called `catppuccin`, but it is not the Catppuccin
palette. It is a Material You palette *re-derived* from a couple of Catppuccin
key colours, so every hue collapses onto one lavender axis:

| Colour   | Real Catppuccin Mocha | caelestia's `catppuccin` mocha |
| -------- | --------------------- | ------------------------------ |
| `base`   | `#1e1e2e`             | `#131317`                      |
| `text`   | `#cdd6f4`             | `#e5e1e7`                      |
| `red`    | `#f38ba8`             | `#c1a5fd` (purple)             |
| `green`  | `#a6e3a1`             | `#c8e3ff` (blue)               |
| `peach`  | `#fab387`             | `#e0c2f9` (lilac)              |

Red and green being purple and blue is what makes it read as "generic dark
purple" rather than Catppuccin. Setting a different `variant` does not help:
`variant` only has an effect on the `dynamic` (wallpaper-derived) scheme —
named schemes are read verbatim from fixed files, see
`caelestia/utils/scheme.py: Scheme._update_colours`.

So this repo ships its own scheme, `catppuccin-true`, built from the official
palette.

## `catppuccin-true`

Generated by [`scripts/caelestia-schemes/generate.py`](../scripts/caelestia-schemes/generate.py)
into `scripts/caelestia-schemes/catppuccin-true/`. It takes the 14 accents plus
the base/surface/overlay/text ramps verbatim from
[catppuccin/catppuccin](https://github.com/catppuccin/catppuccin), and derives
the Material 3 roles caelestia additionally needs (containers, `on*` pairs,
fixed variants) by mixing those palette colours — no new hues are invented.

All four flavours are built: `mocha`, `macchiato`, `frappe` (dark) and `latte`
(light). The generator refuses to write a flavour whose foreground/background
pairs fall below 3:1 contrast, so a tweak to the blend ratios can't quietly
produce grey-on-grey. Current worst case is 3.49:1 (latte).

Regenerate after editing the generator:

```sh
./scripts/caelestia-schemes/generate.py
```

### Installing it

caelestia-cli reads schemes from `<site-packages>/caelestia/data/schemes` and
offers **no user-level override**, so a custom scheme has to be placed inside
the package directory. That means it would be lost on a `caelestia-cli` upgrade
or a Python version bump.

`scripts/install-caelestia-schemes.sh` handles both: it stages the scheme in
`/usr/local/share/caelestia-schemes`, installs `/usr/local/bin/caelestia-sync-schemes`,
and registers a pacman hook (`/etc/pacman.d/hooks/95-caelestia-schemes.hook`)
that re-syncs it after `caelestia-cli` or `python` is upgraded.

```sh
sudo ./scripts/install-caelestia-schemes.sh
caelestia scheme set -n catppuccin-true -f mocha
```

To back it out entirely:

```sh
sudo ./scripts/install-caelestia-schemes.sh --uninstall
```

## Picking a theme

Three ways, in rough order of convenience.

### 1. The dedicated picker (one keybind)

[`scripts/caelestia-theme-picker.py`](../scripts/caelestia-theme-picker.py)
lists every `name · flavour · mode` combination in fuzzel, marks the active one
with `●` and preselects it, and applies on Enter.

It enumerates schemes through caelestia's own Python package rather than a
hardcoded list, so `catppuccin-true` and anything added later appear
automatically. It also exposes the light/dark **mode** of each flavour, which
the built-in picker does not.

Bind it in `hypr/hyprland.lua`, next to the other caelestia extras. `SUPER + T`
is already the terminal, so this uses `SUPER + SHIFT + T`:

```lua
-- Theme picker (scripts/caelestia-theme-picker.py); see docs/caelestia-theming.md
hl.bind(mainMod .. " + SHIFT + T", hl.dsp.exec_cmd(
    os.getenv("HOME") .. "/dotfiles/scripts/caelestia-theme-picker.py"))
```

Then `hyprctl reload`.

`--random` skips the menu and jumps to a random scheme.

fuzzel needs no theming of its own here: caelestia rewrites
`~/.config/fuzzel/fuzzel.ini` from its own template on every scheme change
(`caelestia/utils/theme.py: apply_fuzzel`), so the picker always matches the
theme it is switching away from. For the same reason, **do not stow
`fuzzel/fuzzel.ini`** — it is generated, and stowing it would fight caelestia
for the file.

### 2. Caelestia's built-in picker

Open the launcher (`SUPER + SPACE`) and type `>scheme `. It shows a colour
swatch per scheme, which the fuzzel picker cannot. `>variant ` switches the
Material variant, which only affects the `dynamic` scheme.

The `>` prefix is pinned in [`caelestia/shell.json`](../caelestia/shell.json)
(`launcher.actionPrefix`) so it does not depend on the upstream default.

There is no IPC to open the launcher already in scheme mode — `caelestia shell -s`
exposes only `drawers toggle`, with no way to prefill the search text — which is
why the picker above exists as a separate command.

### 3. The CLI

```sh
caelestia scheme set -n catppuccin-true -f mocha       # or macchiato/frappe/latte
caelestia scheme set -m light                          # flip mode
caelestia scheme set -r                                # random
caelestia scheme get                                   # show current + colours
caelestia scheme list --names                          # what's available
```

Switching applies live: caelestia rewrites its templates for GTK, Qt, btop,
htop, fuzzel, Discord clients, spicetify and the terminal, and pushes colours
to Hyprland over IPC (`~/.config/hypr/scheme/current.lua`).

## Config tracked here

`caelestia/shell.json` is stowed to `~/.config/caelestia/shell.json`. The
active scheme itself is *not* config — it lives in
`~/.local/state/caelestia/scheme.json` and is written by the CLI.

Because `~/.config/caelestia/shell.json` already exists as a real file, stow
will refuse to link over it the first time:

```sh
rm ~/.config/caelestia/shell.json
cd ~/dotfiles && stow .
```
